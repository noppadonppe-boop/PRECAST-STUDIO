# Precast mould presentation

## Approved visual language

Project root: E:/1.0 Project GPT Work/Precast-Module. Read its knowledge/modular-program-current.json and current stage requirements before work. The approved style reference is output/mould-style-sample-p42/TS-C-style-sample-01.png; approval authorizes style, not the hardware geometry inferred by image generation.

Use white studio backgrounds, navy condensed headings, thin grey panel borders, soft realistic shadows, navy support steel, brushed silver contact faces, amber removable inserts and grey concrete. One sheet per registered setup: mould/contact surfaces left, corresponding casting right, exact tag and source-based metadata below, a colour legend and visible development-only footer. Keep casting orientation distinct from installed orientation.

## Source and generation

Resolve the current setup register; never equate48 building products with48 unique moulds. P38 currently has44 setups. Read each setup and view its model-derived board before generating. Use P41 hardware references only for the exact P41 pilot, not as a hardware design for other segments. Never reuse the TS-C rounded profile for A/B/D or node pieces.

Use the available imagegen skill and built-in image tool for the requested realistic raster finish. Supply both a geometry reference and the approved style reference, clearly assigning their roles. Preserve handedness, openings, notches, slopes, thickness relationships and casting orientation. Mesh lines are not concrete joints. Do not add windows, lifting anchors, cages or bracing without source geometry. If only contact surfaces are available, label that panel CONTACT SURFACE STUDY and explicitly state hardware not modelled; do not turn it into an apparently completed engineered assembly. Keep pouring openings open.

For batches make one image per setup, save outputs into a new project revision folder, preserve originals, record full prompts, source hashes, output hashes and review status. Use imagegen's actual saved output path; do not guess paths. Never place private imagery in web public folders.

## Review and delivery

Inspect every result against its source: tag, silhouette, handedness, openings, source dimensions and disclaimers. An attractive image is not proof of assembly, demoulding, clearances or strength. Reject obvious geometry drift; mark unresolved details rather than certify them. Use source CAD/model-derived drawings for dimensions. Do not claim exact CAD fidelity for a generative image.

Provide searchable local index, PNG downloads and an archive when delivering the full set. Integrate only through existing authenticated catalogue artifact routes when website integration is in scope; preserve original/reference access. User approval of this style does not authorize public deployment or production release. Report generated/reviewed counts separately from Stage5 engineering progress.
