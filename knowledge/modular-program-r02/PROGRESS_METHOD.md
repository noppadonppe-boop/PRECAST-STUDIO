# รายงานขั้นและเปอร์เซ็นต์ — ฐาน P20

กติกาการดำเนินงานล่าสุด: [ทำครบ100%แล้วหยุดส่งผู้ใช้ตรวจทุกขั้น](STAGE_REVIEW_GATE.md) ไม่หยุดขอคำสั่งต่อเมื่อจบเพียงงานย่อย และไม่เริ่มขั้นถัดไปโดยอัตโนมัติ ตัวเลข100%ต้องมีหลักฐานผ่านเกณฑ์ของขั้นนั้นจริง

ผู้ใช้ขอให้รายงานทุกครั้งว่าขั้นปัจจุบันทำได้กี่เปอร์เซ็นต์ ให้ขึ้นต้นผลส่งมอบด้วย “ขั้น X/8 — ชื่อขั้น — ความคืบหน้าภายในขั้น Y%” พร้อมสิ่งที่เพิ่มและงานถัดไป หากไม่มีรายการตรวจรับเพิ่ม เปอร์เซ็นต์คงเดิมได้

เริ่มใช้เกณฑ์นี้ตั้งแต่P20 ไม่ย้อนอ้างว่าเคยวัดเปอร์เซ็นต์มาก่อน ฐานการแบ่งรายการเป็นวิธีติดตามที่ผู้ช่วยกำหนด ไม่ใช่น้ำหนักงานที่ผู้ใช้อนุมัติหรือแผนชั่วโมงทำงาน

ขั้น2แบ่ง20รายการ รายการละ5% ให้เครดิตเมื่อมีสิ่งส่งมอบและตรวจในขอบเขตพัฒนาแบบตามที่ระบุ ไม่ให้เครดิตบางส่วนเพียงเพราะเริ่มงาน สูตร=จำนวนรายการDONE/20×100 ค่าเริ่มก่อนP20คือ14/20=70% หลังส่งรูปประสานระดับหัวกรอบครบคือ15/20=75%

ข้อมูลรายการและหลักฐานอยู่ `output/head-interface-p20/stage2-checklist.json` รายงานอ่านค่าจากทะเบียนนี้ ไม่เพิ่มตามจำนวนภาพ/ข้อความ/รอบสนทนา ทะเบียนsnapshotP20ต้องเก็บเป็นประวัติ เมื่อมีผลงานใหม่ให้สร้างsnapshotใหม่และปรับcurrent pointer

ความครบของข้อเสนอไม่ใช่การfreezeขนาดหรือผ่านรับแรง รายการที่มีแบบและผลตรวจเรขาคณิตให้DONEได้แม้วัสดุ/เหล็ก/หูยกรอP7 แต่การตัดสินใจทางgeometryที่กระทบการประกอบต้องสะสางในรายการ20ก่อนส่งต่อขั้น3 ข้อมูลที่ถูกแก้ต้องทบทวนรายการที่ได้รับผลกระทบและอาจลดเปอร์เซ็นต์ได้

หากขอบเขตเปลี่ยนจริง ให้ประกาศแก้ฐานและอธิบายตัวหารใหม่ ห้ามเพิ่มรายการย่อยเพื่อทำให้เปอร์เซ็นต์ดูสูงขึ้น ขั้นอื่นต้องกำหนดรายการตรวจรับของขั้นนั้นก่อนรายงานเปอร์เซ็นต์ ไม่แปลง2/8เป็น25%โครงการ และไม่เฉลี่ยเปอร์เซ็นต์ทุกขั้นโดยไม่มีน้ำหนักงาน

ตัวเลขนี้ไม่ใช่เปอร์เซ็นต์แบบ48สินค้าสำเร็จ ความพร้อมผลิต การอนุมัติวิศวกรรม หรือการประมาณเวลาที่เหลือ
